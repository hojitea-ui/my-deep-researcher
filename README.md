# 딥리서처 6노드 — 식물과 세계사

AIFFEL D48 딥리서처 과제. 수업에서 받은 3노드 딥리서처 `pipeline.py`를 **한 줄도 고치지 않고** 상속해서 6노드로 넓혔고, 실행 과정을 3D 연구 공장으로 보여 주는 웹 화면을 붙였다. 끝난 실행은 기록 파일로 남아 디버거처럼 한 단계씩 다시 볼 수 있다.

- 주제: **식물은 어떻게 세계사의 흐름을 바꾸었는가? — 식량·교역·노동·산업·자본**
- 자료: 한국어 위키백과 문서 40건, 585,318자 (`data/corpus.json`)
- 질문: 10개 (`data/questions.json`)
- 모델: `gpt-4o-mini`, temperature 0

## 구조

```
질문 → ① plan → ② dispatch ⇉ ③ researcher × N → ④ review ─(부족·바퀴 남음)→ ② dispatch
                                                    └────────────→ ⑤ synthesize → ⑥ evaluate
```

| 노드 | 하는 일 | 모델 호출 |
|---|---|---|
| ① 기획 `plan` | 목차를 짜고 절마다 역할과 시작 문서를 붙인다. `pipeline.plan` 그대로 | 1회 |
| ② 배치 `dispatch` | 1바퀴는 모든 절, 2바퀴는 ④가 고른 절만 리서처에게 보낸다 | 없음 |
| ③ 조사 `researcher` × N | 절마다 병렬로 문서를 고르고·읽고·원고를 쓴다. 원고와 함께 '충분/부족'을 스스로 신고한다 | 절마다 여러 번 |
| ④ 점검 `review` | 부족한 절을 골라 다시 보낼지 정한다. 최대 2바퀴 | 없음 |
| ⑤ 종합 `synthesize` | 절마다 마지막 원고를 모아 머리말·맺음말을 붙인다. `pipeline.synthesize` 그대로 | 1회 |
| ⑥ 평가 `evaluate` | 정답표·판정 모델 없이 보고서와 읽은 기록만으로 지표 다섯 개를 센다 | 없음 |

`pipeline.py`의 로직과 프롬프트는 그대로 쓴다. 넓힌 방법은 세 가지뿐이다.

- **상속**: `graph.py`의 `DeepResearch6`이 `pipeline.DeepResearch`를 상속해 ②④⑥ 노드를 더한다. 원고 프롬프트는 `pipeline.write_prompt` 결과에 신고 칸 두 개(충분·부족)와 '전제·인과관계는 자료로 확인된 만큼만 쓴다'는 한 줄만 붙인다.
- **모델 래퍼**: `events.py`가 모델 호출을 감싸 모든 호출을 이벤트로 남긴다.
- **스레드별 절 번호**: 리서처는 병렬로 돈다. `researcher()`가 도는 스레드에 절 번호와 바퀴를 적어 두고, 그 스레드에서 나온 모든 이벤트에 붙인다.

역할 명단·기본 역할 같은 도메인 값은 실행할 때 `config.json` 값을 `pipeline` 모듈에 넣어 바꾼다.

### 다시 보내기 규칙

- 교안 규칙: ④ 점검은 리서처가 '부족'으로 신고한 절만 ② 배치로 돌려보낸다. 다시 보낼 때 지난 원고와 부족 사유를 함께 보내고, 피하기 목록에 다른 절의 시작 문서와 다른 절이 읽은 문서를 넣는다. ④와 ⑤는 그 절의 마지막 원고만 쓴다.
- 이 저장소에서 정한 규칙
  - 2바퀴 시작 문서는 기본으로 지정하지 않는다(자율 재탐색). 부족 사유에 코퍼스 문서 제목이 그대로 적혀 있고, 그 문서가 피하기 목록에 없고 아직 아무도 읽지 않았을 때만 코드로 지정한다.
  - 2바퀴 리서처는 자기가 지난 바퀴에 읽은 문서를 다시 읽지 않는다.
  - **인용 확인** (`check_citations`, 기본 꺼짐): 켜면 ④ 점검이 자기 신고와 별도로 인용을 코드로 확인한다. 원고가 어느 절도 읽지 않은 문서를 인용했거나 인용이 0곳이면, '충분' 신고여도 부족으로 보고 다시 보낸다. 교안 밖 규칙이라 켜고 끌 수 있게 두고 두 경우를 비교한다.

## 설치

Python 3.12와 패키지 세 개(`langgraph`, `langchain-openai`, `python-dotenv`)를 쓴다. Windows에서 [uv](https://docs.astral.sh/uv/)로 만드는 예:

```bash
uv venv --python 3.12 .venv
```

```bash
uv pip install -r requirements.txt
```

## 키

프로젝트 폴더에 `.env` 파일을 만들고 한 줄을 넣는다. `.env`는 저장소에 올라가지 않는다.

```
OPENAI_API_KEY=sk-...
```

`keys.py`는 이 파일에서 `OPENAI_API_KEY` 한 줄만 직접 읽는다. 키 값은 화면·로그·브라우저로 내보내지 않고, 바깥에는 '있다/없다'만 알린다. 키가 없어도 저장된 실행 기록은 재생할 수 있다.

## 실행

### 웹 화면

```bash
.venv/Scripts/python app.py
```

브라우저에서 http://127.0.0.1:8765 를 연다. 포트는 `--port`로 바꾼다.

- **실제 호출**: 질문을 입력하고 `실제 호출로 연구 시작`을 누른다(키 필요). 이벤트가 오는 대로 화면이 움직인다.
- **기록 재생**: `REPLAY` 목록에서 기록을 골라 `기록 재생`을 누른다. 키도 모델 호출도 필요 없다.
- 위쪽 `MODE`에 지금이 실제 호출인지 기록 재생인지 표시된다. 두 경우 모두 같은 이벤트 데이터로 화면 상태를 다시 계산한다.

### 명령줄

```bash
.venv/Scripts/python runner.py --question "후추와 차에 대한 수요는 대항해시대와 유럽의 해외 진출에 어떤 영향을 주었는가?"
```

- `--plan-only`: ① 기획만 한 번 불러 목차·역할·시작 문서를 미리 본다.
- 기록은 `runs/<실행 ID>.jsonl`, 보고서는 `output/reports/<실행 ID>.md`, 요약은 `output/runs.jsonl`에 쌓인다.

### 코퍼스 다시 모으기

```bash
.venv/Scripts/python collect_corpus.py
```

MediaWiki API로 시드 문서 8건(감자·밀·벼·옥수수·후추·차 (음료)·향신료 무역·대항해시대)에서 2홉까지 넓힌다. 3,000자 미만 문서와 동음이의 문서, 주제 관련어(작물·농업·식량·교역)가 1만 자당 10회 미만인 2홉 문서는 뺀다. 뺀 문서와 사유는 `data/corpus_info.json`에 남는다.

## 화면

| 영역 | 내용 |
|---|---|
| 가운데 | 3D 공장. 설비는 실제 이벤트에만 반응한다 |
| 왼쪽 `OPERATIONS` | 실행 정보, 노드별 진행, 코퍼스 크기와 창 사용량 |
| 오른쪽 탭 | `03 EVENTS` 이벤트 목록과 상세(유형·시각·스레드·절 번호, 프롬프트·응답 원문), `04 UNITS` 설비 상세, `05 DOCS` 문서(전체·읽음·안 읽음·여러 절이 읽음), `06 REPORT` 보고서와 `MD 받기` |
| 아래 | 타임라인과 재생 단추, 배속(0.5×~4×) |
| 위 | `L`·`R` 패널 접기, `GFX HI/LO` 그래픽 품질 |

설비와 노드의 대응:

| 설비 | 뜻 |
|---|---|
| `CT-01` 관제탑 | ① 기획 · ② 배치. 작업 지시서를 낸다 |
| `RS-A`~`RS-D` 연구 구역 | ③ 조사. 절 하나가 구역 하나 |
| `QG-04` 검사 게이트 | ④ 점검 |
| `SY-05` 종합 설비 | ⑤ 종합 |
| `MS-06` 계측 스테이션 | ⑥ 평가. 막대 다섯 개가 지표 다섯 개 |
| `WH-00` 자동 창고 | 코퍼스. 상자 하나가 문서 하나 |

구역마다 로봇 두 대가 있다. RU는 자기 구역에서 일하고, DC는 창고에서 문서를, 게이트와 종합 설비로 원고를 나른다. 로봇도 실제 이벤트가 있을 때만 움직인다.

### 키보드

| 키 | 동작 |
|---|---|
| `Space` | 재생 / 멈춤 |
| `←` / `→` | 이벤트 하나 뒤로 / 앞으로 |

어느 시점으로 건너뛰어도 병렬 리서처 상태와 3D 장면이 그 시점과 정확히 맞도록, 화면 상태는 늘 처음부터 그 이벤트까지 다시 계산한다.

### 보고서 받기

`06 REPORT` 탭의 `MD 받기`는 ⑤ 종합이 끝난 시점부터 켜진다. 받은 파일(`report-<실행 ID>.md`)에는 맨 위에 질문·실행 ID·모드·모델·설정, 가운데에 보고서 본문, 맨 아래에 ⑥ 평가 지표 다섯 개가 들어간다. ⑥ 평가 전 시점에서 받으면 지표 자리에 그렇다고 적힌다. 파일은 브라우저가 화면의 이벤트 데이터로 만들므로 서버나 모델을 부르지 않고, 저장된 기록을 재생할 때도 받을 수 있다.

주소 끝에 `?dev=1`을 붙이면 개발 확인용 기록이 목록에 함께 나오고, 브라우저 콘솔에서 설비 관통·떠 있는 물체·로봇 겹침 검사(`__rf.checkOverlaps`, `__rf.checkFloating`, `__rf.simulateRobots` 등)를 돌릴 수 있다.

## 지표 (⑥ 평가)

정답표도 판정 모델도 쓰지 않는다. 만들어진 보고서와 실제로 읽은 기록만 본다.

| 지표 | 뜻 | 지켜보는 장치 |
|---|---|---|
| 근거 비율 | «문서명»이 붙은 문장의 비율 | 절마다 읽는 문서 수, 다시 맡기기 |
| 허위 인용 | 아무도 읽지 않은 문서를 인용한 곳. **0이어야 한다** | 경보 |
| 읽고 안 쓴 문서 | 읽었는데 보고서에 안 나온 문서 | 시작 문서 배정 |
| 편중 | 가장 많이 인용된 문서가 차지하는 몫 | 배정, 피하기 목록 |
| 중복률 | 여러 절이 겹쳐 읽은 몫 | 배정, 피하기 목록 |

문장 자르기는 교안 수치(수업 결과자료 Q4 기본 기록 46문장 중 31문장, 67.4%)를 그대로 재현하는 규칙을 쓴다.

## 실행 기록

지금까지의 실제 실행 두 건. 기록은 `runs/`, 보고서는 `output/reports/`에 있고, 웹 화면에서 재생할 수 있다.

| 실행 | 질문 | 근거 비율 | 허위 인용 | 읽고 안 쓴 | 편중 | 중복률 |
|---|---|---|---|---|---|---|
| `20261106-175622` | Q2 감자·밀·벼·옥수수와 인구·식량 체계 | 73.1% | 0 | 0 | 16.7% | 20.0% |
| `20261106-175316` | Q3 후추와 차 수요와 대항해시대 | 28.3% | **2** | 4 | 42.9% | 12.5% |

두 실행 모두 `check_citations`를 끈 상태(교안 규칙)였다. Q3의 허위 인용 2건은 한 절에서 나왔다.

1. 시작 문서를 읽은 결과가 '관련 없음'이었다.
2. 다음 문서 후보 「알렉산드리아」와 「이집트」가 쉼표로 이어져 보였고, 모델이 "알렉산드리아, 이집트"를 한 제목으로 답했다. 코퍼스에 없는 제목이라 탐색이 끝났다(예산 3건 중 1건만 읽음).
3. 자료 없이 원고를 쓰면서 입력의 꼬리표 `[맡은 절]`을 «맡은 절»로 인용했고, 스스로 '충분'이라 신고했다.
4. ④ 점검은 자기 신고만 보므로 통과시켰고, ⑥ 평가의 허위 인용 경보가 이를 잡았다.

`check_citations`는 이 사례를 계기로 넣었다. 실험 결과와 분석은 `REPORT.md`에 정리할 예정이다.

## 설정 (`config.json`)

| 키 | 값 | 뜻 |
|---|---|---|
| `model` | `gpt-4o-mini` | 모든 노드가 쓰는 모델 |
| `settings.max_sections` | 4 | 절 최대 개수 |

| `settings.redispatch` | true | ④ 점검이 부족한 절을 다시 보낸다 |
| `settings.max_rounds` | 2 | 최대 바퀴 |
| `settings.check_citations` | false | ④ 점검의 인용 확인 |
| `domains.plants.roster` | 역할 6개 | 큰그림 / 기원·전파 / 생산·식량 / 교역·경제 / 인과 검증 / 비교 담당 |
